# loopd 3.0.0

**ai-bridge is now loopd.** The plugin, its marketplace, its command slugs, its role-agent
namespace, its three companions and this repository were renamed. Nothing else about how
the plugin behaves changed in the rename. It is a major version because every installed
copy has to move over by hand.

**5 merged pull requests since 2.4.3**, grouped below.

| | |
|---|---|
| **Upgrading** | [`MIGRATION.md`](../../MIGRATION.md): install `loopd@loopd`, run `/loopd:init` in each bundle, edit three name-scoped files, then uninstall `ai-bridge` |
| **Breaking** | `/ai-bridge:*` → `/loopd:*`, `ai-bridge:<role>` → `loopd:<role>`, `ai-bridge@ai-bridge` → `loopd@loopd`, companions `ai-bridge-*@ai-bridge` → `loopd-*@loopd` |
| **Repository** | `cbmono/ai-bridge` → `cbmono/loopd`. GitHub redirects the old name |

## The rename

| Old | New |
|---|---|
| `/plugin install ai-bridge@ai-bridge` | `/plugin install loopd@loopd` |
| `/ai-bridge:<cmd>` | `/loopd:<cmd>` |
| `ai-bridge:<role>` (dispatch target) | `loopd:<role>`. A bare role name does not resolve |
| `ai-bridge-yolo@ai-bridge` | `loopd-yolo@loopd` |
| `ai-bridge-accounts@ai-bridge` | `loopd-accounts@loopd` |
| `ai-bridge-llm@ai-bridge` | `loopd-llm@loopd` |

**Some names stayed the same on purpose.** A bundle's `.ai-bridge/` directory, the
`_ai-bridge-<group>` folder convention and the launcher names `bin/ai-bridge-claude` and
`bin/ai-bridge-deepseek` are unchanged.

**`ai-bridge@ai-bridge` is an alias for this one release.** It now installs a stub with no
hooks and no agents. Its only skill, `/ai-bridge:renamed`, prints the steps to move. It
does not keep anything working.

**Until you move a companion, it fails safe.** `yolo` projects read as `gated`, and no
account line prints.

## What an existing installation must do

Follow [`MIGRATION.md`](../../MIGRATION.md) §2, in order:

1. `/plugin marketplace add cbmono/loopd`, then `/plugin install loopd@loopd`, then restart Claude Code.
2. Run **`/loopd:init <bundle-path>` in each bundle**. This is the human's step. No agent runs it in someone else's clone.
3. Edit the three files `init` never overwrites: `CLAUDE.md`, `.claude/ai-bridge-statusline.sh` and `.claude/settings.local.json`. Commit the edit.
4. Swap each companion you use for its `loopd-*` name.
5. **Only then** uninstall `ai-bridge@ai-bridge` and remove the `ai-bridge` marketplace.

**If you wrote the optional `claude --bg` grant, change its name too.** It now reads
`Bash(claude --bg * --agent loopd:* --permission-mode bypassPermissions --add-dir *)`.
`/loopd:init` prints that form.

**Edit first, then uninstall.** The cache keeps old versions on disk, so a scripts-path
line you have not edited can keep running stale `ai-bridge` scripts without any error.

## Also in this release

**Auto mode on is now the supported shape.** That means one main thread and the PM
dispatching freely. `init` never writes a `claude --bg` grant or a workspace-trust key, and
prints a notice instead. See `docs/operations.md` → "The supported shape".
